# DFS Optimizer v1.23.0

## One import for results and salaries

In Results & Learning, choose your results and salary folders once, then click **Import Results & Salaries**. The scan includes subfolders and skips already imported contents even when files have moved or been renamed. Original files remain unchanged. Standard NFL salary CSVs and embedded DraftKings entry-file salary tables are supported.

Each results contest is paired with a compatible salary revision. Automatic pairing requires a unique same-date candidate and complete observed player/role coverage. Use **Review Salary Matches** when a choice or missing-date confirmation is needed. Captain and FLEX identities remain separate. Importing salaries does not invent actual scores, fees or prizes, and does not automatically rebuild old analysis. Use **Analyze Saved Results** explicitly for earlier results.

## Results, reports and compute tools together

This release integrates the full configurable Deep-compute feature branch, including opponent portfolio analysis and combined imports (PRs #37, #43 and #44), with the published v1.22.0 reporting tools and AR-01 saved-repair safeguards.

- Compare observed opponent usernames, entry counts, lineup variety, duplication, exposures and pair concentration, including peers with the same number of entries. Missing or unreadable entries remain visible in coverage.
- Export a shareable review ZIP with performance, recorded settings, data quality and issues. Summaries remain the default; lineup details are optional. Known zero, unknown values and qualified cash/ownership evidence remain distinct.
- Configure NFL Classic and Showdown Deep budgets, all-style searches and ranked/portfolio output, with paged results, input snapshots, build archives, saved candidate banks, overnight preparation and scenario reuse.
- Use the branch's forecast review, ownership/projection sensitivity and ranking-repeatability tools. These are model diagnostics; experimental workload, specialist and opponent-model assumptions do not establish predictive accuracy or guaranteed returns. Showdown's generic payout proxy is not contest-specific ROI.

See the [complete user guide](../USER_GUIDE.md) and [feature history](configurable-deep-compute.md) for controls, qualifications and the full incorporated feature scope. The separate automatic portfolio-fallback proposal in PR #42 is not included.

## Repair and import integration

Cancelled, incomplete, stale or mismatched repairs preserve the current saved entries and reports, including edits and valid news updates made since launch. Complete valid repairs apply once, using the ranked output ordering. Deep settings and candidate-library changes invalidate pending saved repairs. Job-owned callbacks and cooperative close handling remain active.

When a cancelled saved repair reaches the feature branch's constrained-selector stop, its worker delivers a cancelled retained-only proposal. The GUI rejects it; it does not open a misleading lineup-shortage dialog or replace saved entries. Non-cancelled shortages and ordinary generated-only behavior remain unchanged. Rejected repair attempts do not create completed output archives or replace the current diagnostic.

Export Review Report stays disabled until an import worker retires. Source imports and analysis use their existing explicit actions; release installation does not backfill history, modify the launcher or move user data.
