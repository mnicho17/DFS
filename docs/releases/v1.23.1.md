# DFS Optimizer v1.23.1 maintenance — pending review

Results & Learning and Review Salary Matches use one authoritative pairing state. A compatible candidate is **READY_TO_PAIR** until an association is saved. **PAIRED** requires a saved association and current source/qualification checks. Missing or incompatible candidates show **NO_COMPATIBLE_MATCH**; a saved association that no longer qualifies shows **INVALID_SAVED_PAIR**, preserves its revision, and is never automatically repaired.

One historical salary revision can be reused across multiple compatible result files from the same slate. Report counts reflect saved associations, not candidate availability: 24 results with 16 saved pairs leave eight unpaired; 24 saved pairs leave zero. Saving refreshes the report immediately. Orphaned pairs and inconsistent counts receive diagnostic warnings. Readable-roster coverage includes the total and percentage; unreadable rows remain excluded.

Review ZIPs default to the external user-data **review-reports** folder, normally `%LOCALAPPDATA%/DFS Optimizer/review-reports`, beside **history**. External data-directory overrides use their own **review-reports** folder. Checkout paths and captured history trees are excluded from the default. The normal Save dialog still allows another destination and asks before replacing an existing report; the final path remains visible. Source history stays read-only and source-updater checks are unchanged.

This maintenance change preserves AR-02 portfolio recovery and AR-01 saved-repair safeguards. It does not change strategy, projections, ownership, SIM scoring, payouts, or historical model tuning. No release is published by this review PR.
