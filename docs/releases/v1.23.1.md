# DFS Optimizer v1.23.1 — Portfolio & Results Reliability

This maintenance release includes the already-merged reliability improvements from PRs #45 and #46.

## Portfolio Recovery

Short Showdown portfolios can recover when automatic exposure guardrails are too restrictive. Normal candidate generation and scoring, strict selection, and strict repair run first. If the portfolio is still short, recovery may increase only automatic total-player, Captain, and combined K/DST Captain guardrails through bounded stages, stopping at the first complete valid portfolio.

Explicit player exposure limits, Captain limits, locks, fades, minimum uniqueness, groups, team/game limits, salary and roster eligibility, and retained rows remain hard constraints. Diagnostics disclose the strict and final selected counts, starting and effective automatic caps, and recovery stage. Increased automatic concentration is clearly shown as a review item.

Candidate coverage can improve before final scoring. Deep work uses only its remaining compute budget; saved libraries are not extended and new candidates are not introduced after final scoring. Cancellation never starts automatic recovery. AR-01 cancellation and saved-repair safeguards remain intact.

## Results & Learning

Results & Learning and Review Salary Matches now share one authoritative pairing state:

- **PAIRED:** a saved association exists and still qualifies.
- **READY_TO_PAIR:** a compatible salary revision exists but has not been saved.
- **NO_COMPATIBLE_MATCH:** no current compatible revision is available; rejection reasons explain why.
- **INVALID_SAVED_PAIR:** the existing saved revision is preserved and flagged instead of being silently retargeted or repaired.

One salary slate can be reused across multiple compatible result files. Counts reflect saved relationships rather than candidate availability: 24 results with 16 saved pairs leave eight unpaired; 24 saved pairs leave zero. Saving updates the report immediately. Invalid or orphaned saved pairs receive diagnostics. Readable-roster coverage now includes the total and percentage, with unreadable rows still excluded.

## Review Reports

Generated `DFS-Review` ZIPs default to an external user-data `review-reports` directory, normally `%LOCALAPPDATA%/DFS Optimizer/review-reports`. External data-directory overrides use their own `review-reports` folder. Reports no longer default into the Git checkout and interfere with safe source updates.

Users may still choose another destination. Existing overwrite confirmation, cancellation, atomic publication, and source-history protections remain unchanged. The final saved path remains visible.

## No Strategy or Model Changes

Projection formulas, ownership formulas, SIM scoring/ranking formulas, payout modeling, and historical auto-learning/tuning are unchanged. This release finalizes documentation and packaging for the merged reliability work; it adds no further optimizer or Results & Learning behavior changes.
