# DST research capture and sampling adapter

This research-only adapter implements the sampling declaration in the [prospective protocol](DST_MARGINAL_PROSPECTIVE_PROTOCOL.md). It reads no files or outcomes, writes no receipts, modifies no history and is not wired into Generate, background preparation or production simulation.

`capture_inputs` accepts exactly two explicitly identified opposing DSTs, canonical game/player keys, frozen forecasts, aware pregame timestamps, source SHA-256 receipts, model hash and pregame-evidence hash. It rejects duplicate keys, conflicting teams/opponents, partial identity, unsupported forecasts, missing hashes, out-of-window games and captures at/after kickoff. Identical DST records are not a valid two-defense fixture. It canonicalizes defense ordering and returns a detached SHA-256 envelope. `verify_capture` rebuilds the canonical envelope and rejects modifications, extra fields and qualification claims.

These are **unqualified captures**. Caller-provided hashes/timestamps are assertions. A reproducible or rehashed envelope is not evidence of trustworthy timing, source contents, actual identity or historical eligibility. External immutable pre-outcome registration, runtime/source verification, frozen input content verification and existing historical qualification remain required before any prospective result. No local-clock or file-mtime shortcut qualifies a game. The adapter has no authority to promote a capture to qualified status.

`sample_capture` verifies the envelope, then returns only unqualified candidate DST samples: three fixed seeds, 2,000 draws per seed for each of two defenses and three factors. It uses the declared compact JSON/SHA-256 local random.Random streams, common standard normals across factors and distinct defense keys. No sample recentering, new forecast or parent/global RNG use occurs. Floor forecasts produce constant -4. Original offense/K/manual/protected draws are outside this API and cannot be edited by it; integrated comparison must still assert their exact parity. Samples preserve analytic means in distribution, not exact finite-sample means. Reproducibility requires the same Python/runtime and pinned code; model/source hashes alone do not certify runtime equality.

Eleven new regressions cover deterministic detached/order-invariant captures, tampering and false qualification, duplicate/conflicting identity in both orders, partial/missing/extra/actual fields, timestamp/window bounds, malformed hashes/forecasts, fixed sample count/floor and input/global/parent RNG preservation, an independent seed oracle/common normals, degenerate forecasts, cancellation before/mid-run and immediately before final return. All 43 focused tests pass with no unexpected network attempts. Complete-suite and Windows package verification are tracked on the PR head separately.

The original v1 plan and its source hashes are retained unchanged. This implementation is additive: no listed v1 source file changes, no historical results are read, and no new predictive conclusion follows. Before execution, the immutable run manifest must additionally pin this adapter, specification, all dependencies, Python/runtime and actual pregame receipts. The next accepted step is trusted pregame receipt registration and source/qualification integration, followed by the bounded scorer after the declared window closes. No collection automation, historical evidence reconstruction, production activation, merge or release is part of this change.
